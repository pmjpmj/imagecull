# 06: 401 and 403 abort the run

Status: resolved (2026-11-02)
Type: task
Spec: `.scratch/cloudflare-clef/spec.md`

**What to build:** two error kinds, `Http401` and `Http403`, both `Recovery::AbortRun`,
so a bad or expired token costs one request instead of a shoot.

## Why

`ErrorKind::from_status_code` maps 400/413/422/5xx and nothing else, so a 401 lands
in `failure()`'s `unwrap_or(ErrorKind::BadResponse)` — which is `Recovery::Continue`.
Against a keyless local server that never happens. Against Workers AI it is the
single most likely failure there is (expired token, wrong account id, token without
Workers AI permission), and the run would pay for 400 of them.

## The work

- `ErrorKind::Http401`, `ErrorKind::Http403`; `as_str` → `"http_401"`, `"http_403"`;
  `from_status_code`: `401 => Http401, 403 => Http403`; `recovery`: both
  `Recovery::AbortRun`, beside `Http400`/`Http422` and with the same one-line reason
  ("every remaining frame would fail the same way").
- `ErrorKind::ALL` grows to 15 — the const's length and any exhaustive test.
- `failure()`'s advice for both: name the credential, never the value —
  `— the server refused this run's credentials; check [server] token_env (or
  [server] token) and the account the endpoint names`.
- The `from_status` round-trip test and `ALL`'s ordering follow spec order: put the
  two new kinds after `Http400`, before `Http413`.

## Tests

`crates/imagecull-core/src/error.rs`:

- `from_status_code(401) == Some(Http401)`, `403 == Some(Http403)`.
- `recovery()` for both is `AbortRun`.
- `ALL` round-trips through `from_status`.

`crates/imagecull-core/tests/systemone_http.rs`:

- A mock answering 401 to the first request: `decide` returns `Http401`, and the
  message contains `token_env` and not the token value.

`crates/imagecull-core/src/scoring.rs` (or the CLI's score path, wherever
`Recovery::AbortRun` is honoured): a run over three fakes whose decider answers 401
on every call issues **one** request and ends `AbortRun`, mirroring the existing
abort tests for `Http400`.

## Comments

**Implemented 2026-11-02.** `Http401` and `Http403` sit after `Http400` and before
`Http413` in the enum, `ALL` and `as_str`; both are `AbortRun`; `failure()` advises
the credential source for both and never the value. Four notes:

1. **The abort test lives in `tests/failure_taxonomy.rs`, not `src/scoring.rs`.**
   The ticket allowed "wherever `Recovery::AbortRun` is honoured", and that is
   `Judged::stops_run` — a private method with no seam of its own. Every other
   run-level abort test (`a_rejected_rubric_stops_the_run_at_the_first_frame`,
   `a_malformed_body_stops_the_run_too`) is an integration test on `scoring::run`
   in that file, so the 401 case is the third of that family:
   `a_refused_credential_stops_the_run_at_the_first_frame`.
2. **`SPEC.md` §10 gained its two rows.** The table is the taxonomy's contract and
   a status the code can write but the spec does not list is a doc bug. §11.1's
   `[server]` key list is still missing `path`, `selector`, `token_env`, `token`
   and `truncate`, and `[group] max_images` — that sweep is ticket 08's.
3. **Workers AI's error body is still appended raw.** Its `{"success": false,
   "errors": [{code, message}], "result": null}` has no `detail`, so `detail()`
   falls back to the whole body before the advice. Ticket 09 says a one-line change
   to `detail` belongs here *if* the live message is unreadable, and ticket 09's
   answer is still open, so nothing was guessed at: the advice still lands, and the
   JSON is ugly rather than wrong. Worth doing once a real 401 body is recorded.
4. **`groups` is unchanged, and 401s there still cost one request per group.**
   `cull::run` has no `AbortRun` handling at all — a failed comparison is an
   undecided group and the pass continues, which is how `Http400` already behaves.
   The ticket scoped itself to the run, so this landed there; a 401 sweep for a
   cull is a separate change (and a pre-existing gap, not one this ticket opened).
